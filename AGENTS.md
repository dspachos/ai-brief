# AGENTS.md — The AI Brief repo

Daily AI news briefing. Static site on GitHub Pages, generated by a pi agent; two MCP servers expose the same content as tools. Keep all three surfaces in sync.

## Daily workflow

`pi` in this repo → `/briefing` (`.pi/prompts/briefing.md`). It searches (Exa, `recencyFilter: day`), reads RSS (`feeds.txt`), pulls quotes (`scripts/quotes.py`), writes `posts/YYYY-MM-DD.html` from `template.html`, prepends to `posts.json`, rebuilds `search.json` (`scripts/build_search.py`), commits and pushes. Pages redeploys on push (10-min edge cache — don't "fix" stale JSON, wait).

Invariants: never overwrite an existing day's post; every item links a source (no fabrication); `posts.json` newest-first; `search.json` is generated, never hand-edited.

## The three surfaces

| Surface | Files | Changes go live via |
|---|---|---|
| Site (Pages) | `index.html`, `archive.html`, `posts/*.html`, `template.html` | `git push` |
| Local stdio MCP | `scripts/mcp-server/server.mjs` (distributed via `npx -y github:dspachos/ai-brief`) | push (users need `npx clear-npx-cache`) |
| Remote MCP | `worker/index.mjs` → https://ai.optiread.app/mcp (Cloudflare Worker, free tier) | `cd worker && npx wrangler deploy` |

**Tool names/descriptions and markdown output must stay identical across both MCP servers** — edit `worker/index.mjs` and `scripts/mcp-server/server.mjs` together, then deploy the worker. Tool names are public API (permission rules reference them) — don't rename; evolve descriptions freely. Server-side `instructions` (in the `McpServer` constructor) is how behavior ships to clients — never rely on client-side config like CLAUDE.md.

## Site conventions

- No build step: Tailwind + Alpine via CDN, plain HTML, relative paths (works under the `/ai-brief/` subpath).
- kami palette via inline `tailwind.config`: `paper/ink/body/muted/hair/brand` + `gain/loss`. Base font scale is `html { font-size: 106.25% }` — px-based font classes were converted to rem for this.
- Post structure is machine-parsed (by `build_search.py`): `<section id="…">` with `<h2>`, `<article><h3><p>`, markets `<p>` commentary, quick-hits `<li>`. `template.html` changes must keep this shape.
- Item links in MCP output are inline `[[N]](url)` markers — no appendix (models rewrite/drop appendices).

## Gotchas

- `add-mcp` infers the server name from the URL (→ `optiread`); always pass `--name ai-brief`. It also replaces the whole `mcpServers` block instead of merging.
- Worker reads live `posts.json`/`search.json` from Pages — data fixes need only a repo push, no worker deploy.
- Quotes come from Yahoo Finance chart API (stooq is dead). RSS failures are skipped, never fatal.
- Deploy output may lag a few seconds before the endpoint serves new code.

## Commands

```bash
python3 -m http.server 8080                     # local preview (fetch needs http, not file://)
python3 scripts/build_search.py --check         # rebuild + verify search index
cd worker && npx wrangler deploy                # deploy remote MCP
npx add-mcp https://ai.optiread.app/mcp --name ai-brief --agent <agent>  # install remote MCP
```
